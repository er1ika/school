# KeyGuard — менеджер паролей для браузера

**Учебный проект для 10 класса.** Расширение для Chrome/Edge на Manifest V3, которое хранит пароли, карты и заметки в зашифрованном виде, умеет автозаполнение, генерацию паролей, TOTP-коды и аудит утечек.

> Ветка проекта: `arena/cb7954fe-school`. Репозиторий: `er1ika/school`.

---

## Возможности

| Возможность | Как работает |
|---|---|
| 🔐 **Шифрование** | Мастер-пароль → PBKDF2-SHA256 (310 000 итераций) → ключ AES-256-GCM. В `chrome.storage.local` попадает только шифротекст. |
| 🔑 **Хранилище** | Логины, банковские карты и заметки. Поиск, избранное, категории, редактирование и удаление. |
| ⚡ **Автозаполнение** | Контент-скрипт находит форму логина и подставляет логин/пароль по команде. После отправки формы предлагает сохранить или обновить пароль. |
| 🎲 **Генератор** | Криптостойкий генератор (`crypto.getRandomValues`) с длиной 8–64, выбором наборов символов и режимом без похожих символов. |
| 📊 **Надёжность** | Оценка пароля по энтропии и эвристикам: слабый / средний / надёжный / отличный. |
| 🛡️ **Аудит** | Находит слабые, повторно используемые и устаревшие (старше 180 дней) пароли. |
| 🌐 **Проверка утечек** | Проверка по базе [Have I Been Pwned](https://haveibeenpwned.com/) через k-anonymity: серверу уходит только 5 символов SHA-1-хеша. |
| 📱 **TOTP** | Генерация кодов двухфакторной аутентификации (RFC 6238, SHA-1, 6 цифр, 30 секунд) с таймером. |
| ⏱️ **Автоблокировка** | По таймеру бездействия и через Chrome Idle API. Ключ стирается из памяти. |
| 📋 **Буфер обмена** | Копирование пароля и автоматическая очистка через 15–120 секунд. |
| 💾 **Резервные копии** | Экспорт/импорт зашифрованного JSON-файла для переноса между устройствами. |
| 🎨 **Интерфейс** | Тёмная тема, стеклянные карточки, адаптивная страница настроек, без внешних библиотек. |

## Быстрый старт

### 1. Загрузка расширения

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите **Режим разработчика** (Developer mode).
3. Нажмите **Загрузить распакованное расширение** (Load unpacked).
4. Выберите папку с проектом (например, `school`).
5. Закрепите иконку KeyGuard на панели браузера.

> Расширение не устанавливается из магазина — это нормально для учебного проекта. Для Chrome/Edge достаточно папки с `manifest.json`.

### 2. Создание хранилища

1. Нажмите на иконку KeyGuard.
2. Придумайте мастер-пароль (минимум 8 символов, лучше 12+ с цифрами и символами).
3. Повторите его и нажмите **Создать хранилище**.
4. **Обязательно сохраните мастер-пароль.** Он не хранится нигде, восстановить его невозможно.

### 3. Добавление записи

1. Нажмите **+** в правом нижнем углу.
2. Выберите тип: логин, карта или заметка.
3. Заполните поля. Пароль можно сгенерировать кнопкой с «волшебной палочкой» и проверить на утечки.
4. Нажмите **Сохранить**.

### 4. Автозаполнение на сайте

1. Откройте сайт с формой входа.
2. Нажмите на иконку KeyGuard → выберите запись → нажмите **«Заполнить»** (или используйте контекстное меню поля пароля → «Заполнить паролем из KeyGuard»).
3. Расширение подставит логин и пароль.
4. После отправки формы KeyGuard предложит сохранить новый пароль или обновить существующий.

> Автозаполнение работает на обычных HTML-формах. На сайтах с нестандартными формами (React-контролы, iframe) может не сработать — это ограничение учебного проекта.

## Интерактивный макет

Чтобы посмотреть интерфейс без установки расширения, запустите локальный сервер из корня проекта:

```bash
npm run serve
```

Затем откройте <http://localhost:8000/preview.html>. В макете работают поиск, карточки, раскрытие пароля, генератор, редактор и удаление записей. Используются выдуманные данные, а мастер-пароль не проверяется — подойдёт любой непустой пароль.

> Макет не использует настоящее шифрование и не сохраняет изменения. Настоящий менеджер работает только в установленном расширении.

## Демо-сайт для проверки

В папке `demo-site/` находится «Школьный портал» — обычный сайт с двумя формами: вход и смена пароля.

```bash
# из корня проекта
npm run serve:demo
# затем откройте http://localhost:8000
```

Или вручную:

```bash
cd demo-site
python3 -m http.server 8000
```

Что проверить:

1. Создайте в KeyGuard запись с логином `student@school10.ru` и паролем `SchoolPass!2026`.
2. Откройте `http://localhost:8000`, нажмите на иконку KeyGuard и заполните форму.
3. Введите пароль в форму и отправьте её — появится баннер «Сохранить пароль в KeyGuard?».
4. Измените пароль во второй форме и отправьте — KeyGuard предложит **обновить** запись.
5. Нажмите на иконку KeyGuard на панели → «Настройки» → «Аудит паролей», чтобы увидеть проверку.

> Важно: расширения не работают на `file://`, поэтому демо-сайт нужно запускать через локальный HTTP-сервер.

### Поток данных

```
Мастер-пароль
      │
      ▼
PBKDF2-SHA256 (310 000 итераций + случайная соль)
      │
      ▼
Ключ AES-256-GCM  ────────►  chrome.storage.session (до перезапуска)
      │
      ▼
Зашифрованный конверт { entries, notes, cards }  ────────►  chrome.storage.local
      │
      ▼
Service worker (background.js) ──► popup / options / content script
```

- **Мастер-пароль** нигде не сохраняется.
- **Ключ** живёт в памяти service worker и в `chrome.storage.session`; при блокировке, простое или перезапуске браузера он стирается.
- **Соль** случайная, хранится в открытом виде рядом с шифротекстом.
- **Verifier** — отдельный зашифрованный маркер, по которому проверяется правильность мастер-пароля.
- **IV** генерируется случайно на каждое шифрование, поэтому одинаковые записи дают разные шифротексты.
- **Смена мастер-пароля** создаёт новую соль и новый ключ и заново шифрует всё хранилище.

### Почему это безопасно

- Используются встроенные Web Crypto API браузера, а не самописные алгоритмы.
- PBKDF2 с 310 000 итерациями делает перебор мастер-пароля дорогим.
- AES-GCM проверяет целостность: изменённый шифротекст не расшифруется.
- Сравнение verifier и паролей защищено от timing-атак (сравнение за постоянное время).
- Пароли не попадают в логи, консоль или открытый текст на диск.
- Ключ не передаётся в popup и content script: они общаются с service worker сообщениями.

### Ограничения

- Нет облачной синхронизации и восстановления мастер-пароля.
- Автозаполнение рассчитано на обычные формы и может не работать на сложных сайтах.
- Проверка утечек требует интернета и обращения к HIBP.
- Очистка буфера обмена зависит от политики браузера и активной вкладки.
- Это учебный проект, а не сертифицированный менеджер паролей. Для реальных данных лучше использовать проверенные open-source решения.

## Как защищать проект

### План выступления (5–7 минут)

1. **Проблема.** Люди забывают пароли, записывают их на стикерах или используют один пароль для всех сайтов. Из-за этого страдают аккаунты.
2. **Решение.** KeyGuard — расширение, которое хранит пароли в зашифрованном виде и помогает создавать надёжные пароли.
3. **Как устроена защита.** Мастер-пароль → PBKDF2 (310 000 итераций) → ключ AES-256-GCM → зашифрованные записи. Мастер-пароль не сохраняется.
4. **Функции.** Хранилище, автозаполнение, генератор, аудит, TOTP, проверка утечек, резервные копии, автоблокировка.
5. **Тестирование.** 82 теста логики и 34 UI-теста: криптография, смена мастер-пароля, бэкап/импорт, формы, аудит.
6. **Ограничения.** Нет облачной синхронизации и восстановления пароля; автозаполнение работает не на всех формах.
7. **Вывод.** Проект показал, как браузерные расширения и Web Crypto API позволяют сделать безопасный инструмент без внешних библиотек.

### Возможные вопросы комиссии

**Где хранятся пароли?**
В `chrome.storage.local` в зашифрованном виде. Открытый текст есть только в памяти на время работы.

**Можно ли восстановить мастер-пароль?**
Нет. Он не сохраняется и не передаётся на сервер. Если его забыть, данные не восстановить — это осознанный компромисс безопасности.

**Почему используется PBKDF2, а не просто SHA-256?**
PBKDF2 с 310 000 итерациями и солью делает перебор мастер-пароля очень медленным. Один и тот же пароль с разной солью даёт разные ключи.

**Почему AES-GCM?**
Это аутентифицированное шифрование: оно не только шифрует, но и проверяет целостность. Если изменить шифротекст, расшифрование не сработает.

**Как проверяются утечки без отправки пароля?**
По схеме k-anonymity: вычисляется SHA-1-хеш пароля, серверу отправляются только первые 5 символов. Сервер возвращает список совпадений, а расширение ищет нужный суффикс локально.

**Какие разрешения используются и зачем?**
`storage` — для шифротекста; `activeTab`/`scripting` — для автозаполнения; `clipboardWrite` — для копирования; `idle`/`alarms` — для автоблокировки; `contextMenus` — для пункта в контекстном меню; `host_permissions` — для доступа к сайтам и HIBP.

**Что не реализовано?**
Облачная синхронизация, восстановление пароля, импорт из CSV, поддержка passkeys и сложных нестандартных форм. Это направления для доработки.

**Почему проект безопасен, если он учебный?**
Используются встроенные криптографические API браузера, а не самописные алгоритмы. Но проект не проходил независимый аудит, поэтому для реальных данных лучше использовать проверенные менеджеры паролей.
